> 一条从 C++ 小白到 C++ 20 活地图的爬坑之路。

## 前言：C++ 是什么？值得学吗？

想象你有一把瑞士军刀——C++ 就是编程界的瑞士军刀。它既能做**螺丝刀**（写操作系统驱动），也能做**开瓶器**（写游戏引擎），还能做**剪刀**（写高性能后端服务）。别的语言可能只擅长其中一样，C++ 是全都要。

**但代价是什么？** 学习曲线陡。随便一个 C++ 报错就能给你输出几百行，编译器骂人都不带重样的。

**那为什么还要学？** 因为学会了 C++，你再看其他语言就像开了上帝视角——Python 的列表推导式？C++ 模板玩得更花。Java 的面向对象？C++ 的多态零开销。Rust 的内存安全？C++ 的 RAII + 智能指针也能做到七八分。

**C++ 的大版本，一句话说清：**

| 版本 | 一句话 |
|:---|:---|
| **C++98** | C++ 的"宪法"，基本语法和标准库都在这版定下来了 |
| **C++11** | **现代 C++ 的起点**。auto、智能指针、移动语义、lambda——这版之后 C++ 几乎换了一张脸 |
| **C++14** | C++11 的"小补丁"，修了点小毛病，加了点小糖 |
| **C++17** | **当前企业最主流**。结构化绑定、if constexpr、filesystem——写起来更顺手了 |
| **C++20** | **这是你正在学的**。Concepts、Ranges、Modules、format——C++ 又年轻了一回 |
| **C++23** | 刚出的热乎版本，企业还没怎么用，了解一下就行 |

**企业里到底用哪个？** 现实很骨感：老项目可能还在 C++11 甚至 C++98（是的，2026 年了还有人在用），新项目基本是 C++17 起步，拥抱 C++20 的团队在快速增加。

> 💡 **聪明人的学法：** 学最新的 C++20，看到老代码能看懂就行了。好比你会开自动挡汽车，手动挡也能开——就是起步慢点。

## 第一关：基本功——变量、函数和编译期计算

> 🟢 这一关的内容，从 1998 年到今天没怎么变过。它们是 C++ 的"普通话"。

### 1.1 你的第一个 C++ 程序

任何编程语言的第一步，都是在屏幕上打声招呼：

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, C++20!" << std::endl;
    return 0;
}
```

看不懂这些行？没关系，逐句翻译成人话：

- `#include <iostream>` 就像去图书馆借书——`iostream` 是一本关于"输入输出"的书，你要用到它就必须先借过来。
- `int main()` 是你的程序大门，程序从这里进去，也从这里出来。**每个 C++ 程序有且只有一个**大门口。
- `std::cout << "..."` 是"把文字打印到屏幕上"的意思。`<<` 就是一个小铲子，把右边的文字铲到左边的输出流里。
- `std::endl` 是换行。就像打字打到行尾按回车。
- `return 0` 告诉操作系统："我干完了，一切正常。"

### 1.2 变量——用来装数据的盒子

变量就像一个个贴了标签的盒子，标签上写着"这里面装的是 int"或"这里面装的是 double"，不能乱塞：

```cpp
int age = 25;        // 年龄，整型，4 字节
float price = 9.99;  // 价格，单精度浮点，4 字节
double pi = 3.1416;  // 圆周率，双精度浮点，8 字节
char grade = 'A';    // 成绩等级，单个字符，1 字节
bool is_ok = true;   // 是否成功，布尔值，true/false
```

**有个偷懒的写法——`auto`：**（C++11 引入的）

```cpp
auto age = 25;   // 编译器自己猜：哦，这是个 int
auto pi = 3.14;  // 编译器自己猜：哦，这是个 double
```

省得你写那些啰嗦的类型名。注意了，`auto` 不是"随便"的意思——类型一旦确定就**不能变**，这和 JavaScript 的 `var` 完全不一样。

**为什么 C++ 对类型这么较真？** 因为 C++ 编译后会变成机器码，机器码需要知道每个数据占几个字节、怎么处理。类型就是这些信息的标签。这叫**静态类型**——编译时就定死了，不会运行时才说"哦我搞错了"。

### 1.3 函数——把代码装进箱子里

函数就是把一段有名字的代码打包起来，随用随调：

```cpp
// 定义（def）一个叫 add 的函数
int add(int a, int b) {
    return a + b;
}

// 使用（call）
int result = add(3, 4);   // result = 7
```

**函数就像做菜的一道工序：** 把食材（参数）扔进去，经过处理（函数体内的代码），端出成品（返回值）。

一个重要的区别：**声明 vs 定义**。声明就是告诉编译器"有这么个函数"，定义才是"这个函数具体干啥"。就像餐厅的菜单（声明）和后厨的做法（定义）。

### 1.4 传值 vs 传引用——复制一份还是直接上手

这是 C++ 新手最容易栽坑的地方。想象你有一张写满笔记的纸：

```cpp
void func(int param) {
    param += 1;   // 在这张纸的复印件上加 1
}
// 原版纸还是原来的数

void func_ref(int& param) {
    param += 1;   // 直接在原件上改
}
// 原版纸变成 +1 后的数
```

| 传法 | 像什么 | 特点 |
|:---|:---|:---|
| **传值** `void f(T x)` | 复印一份 | 函数内随便改，不影响外面。安全但慢（大对象复制很贵） |
| **传引用** `void f(T& x)` | 直接上手 | 改了外面也跟着变。快但危险（不小心就改了不该改的） |
| **常引用** `void f(const T& x)` | 只许看不许摸 | 又快又安全。大对象就该这么传 |
| **传指针** `void f(T* x)` | 给个地址自己去拿 | 灵活但容易出现空指针 |

**实用口诀：** 小数据传值，大数据传 `const&`，需要改外面就传引用或指针。

### 1.5 static——让变量"记住"上一次的值

普通的局部变量，函数一结束就销毁了。加上 `static`，它就像有了记忆：

```cpp
void counter() {
    static int count = 0;   // 只初始化一次
    count++;                // 每次调用 +1
    std::cout << count;
}
```

第一次调用：输出 1
第二次调用：输出 2（它还记得上次是 1）
第三次调用：输出 3

**static 三个作用：**

1. **函数内 static**：局部变量变长寿，函数结束不销毁
2. **文件内 static**：这个变量/函数只能在这个文件里用（相当于"私有的"）
3. **类 static**：所有对象共享同一个变量（比如统计一共创建了多少个对象）

### 1.6 constexpr——让编译器帮你加班

有些计算在程序运行前就能算出来。比如斐波那契数列的第 20 项——反正运行结果都一样，为什么不提前算好？

```cpp
constexpr unsigned long long fibonacci(int i) {
    if (i <= 1) return i;
    return fibonacci(i - 1) + fibonacci(i - 2);
}

constexpr auto FIB20 = fibonacci(20);
// 编译期就算出来了！运行时直接拿结果，零开销。
```

**`constexpr` 的进化史，很重要：**

- **C++11：** 能做的事很少，只能 return 一条表达式
- **C++14：** 可以写循环和 if 了
- **C++20（你现在学的）：** 大爆发！可以 `new`、`delete`、用 `vector`、`string`，甚至 `try/catch`！

> 💡 **一个帮助理解的概念：** 你在代码里写 `for (int i = 0; i < 100; ++i)` 这种循环，普通时候它在运行时跑；加了 `constexpr`，编译器在编译期就替你跑完了。你的程序运行时直接拿到了最终结果。

## 第二关：内存与指针——C++ 最强大的武器

> 学完这一关，你会理解为什么 C++ 能做游戏引擎、操作系统、数据库——因为它能直接操作内存。

### 2.1 数组——一排连续的储物柜

数组就像一排编号的储物柜，每个柜子里放一个数据：

```cpp
int arr[5] = {10, 20, 30, 40, 50};
// 柜子编号： 0    1    2    3    4
// 内容：    10   20   30   40   50

arr[2] = 99;          // 把 3 号柜子的内容换成 99
int x = arr[0];       // 从 1 号柜子取出 10
```

**数组的两个致命弱点：**

1. **下标从 0 开始**——这不是为了刁难你，是因为内存地址也是从 0 开始算的。`arr[i]` 就是"从 arr 的起始地址往后走 i 步"。
2. **数组传参时会"退化"成指针**——你传的是一个数组给函数，函数收到的只是一个地址，长度信息丢了。这也是后来 `std::array` 和 `std::vector` 存在的原因（后面会讲到）。

### 2.2 指针——内存地址就是你的 GPS

指针存的是"另一个变量的地址"。有了地址，你就可以远程操控那个变量：

```cpp
int x = 42;
int* ptr = &x;        // ptr 存的是 x 的地址（相当于 x 的门牌号）

*ptr = 100;           // 通过门牌号进去，把房间里改成 100
std::cout << x;       // 输出 100（确实被改了）

ptr + 1;              // 指针做加法，不是加 1 个字节，而是加 1 个 int
                      // （4 个字节），指向下一个 int 的位置
```

**指针的黄金三原则（记住能少踩 90% 的坑）：**

1. **初始化！** `int* p = nullptr;` —— 不要留野指针
2. **检查！** `if (p) { *p = ...; }` —— 解引用前确定它不是空的
3. **释放！** `delete p;` —— `new` 了就要 `delete`，`new[]` 了就要 `delete[]`

> 💡 **指针为什么是 C++ 的灵魂？** 因为你可以用指针精准操作内存中的每一个字节。游戏里的人物坐标、图片的每个像素、网络数据包的每个字段——底层都是用指针在读写的。

### 2.3 循环——重复的事让机器去做

人有三件事做不过机器：算得快、记得牢、**不嫌烦地重复**。循环就是让机器干重复活的工具。

```cpp
// 最传统的 for 循环——"从 i=0 做到 i<10"
for (int i = 0; i < 10; ++i) {
    // 这段代码执行 10 次
}

// 范围 for（C++11）——"对于数组里的每个元素"
int arr[] = {1, 2, 3, 4, 5};
for (auto& x : arr) {      // & 表示引用，改了 x 就是改数组
    x *= 2;                 // 每个元素翻倍
}
```

**普通 `for` 和范围 `for` 的区别：** 普通 `for` 是你亲自告诉机器"从哪开始、到哪结束、每次怎么走"；范围 `for` 是你跟机器说"这个集合里的每个元素，你帮我遍历一遍"——更省心、更安全。

### 2.4 枚举与联合体——给数字取名字，让内存"一物多用"

**枚举：** 把 0、1、2 这种冷冰冰的数字，改成有意义的名称：

```cpp
// 旧式枚举——"污染"了外面的命名空间
enum Color { RED, GREEN, BLUE };

// 作用域枚举（C++11）——推荐，不会污染
enum class Color { Red, Green, Blue };
Color c = Color::Red;      // 必须写 Color::，不会和其他名字冲突
```

**联合体：** 同一块内存，不同的时候存不同的东西。有点像你桌上的台灯——白天放书，晚上放手机，地方还是那个地方，但用途不同。

```cpp
union Value {
    int i;
    float f;
};

Value v;
v.i = 42;       // 现在这块内存当做 int 用
v.f = 3.14f;    // 现在同一块内存当做 float 用（之前的 int 数据被覆盖了）
```

联合体通常配合枚举一起用——用枚举记住"现在这块内存存的是什么类型"，这就是"标签化联合体"。

### 2.5 结构体——把相关的数据捆在一起

```cpp
struct Point {
    int x;
    int y;
};

Point p = {10, 20};    // 创建了一个点(10, 20)
p.x = 30;              // 修改 x 坐标
```

**`struct` 和 `class` 的区别：** 有且只有一个——`struct` 的成员默认公开（public），`class` 的成员默认私有（private）。其他**完全一样**。

>C++17 的结构化绑定让你可以一口气拆开结构体：
>
>```cpp
>auto [x, y] = p;  // x = 10, y = 20
>```

### 2.6 手动内存管理——你 new 的，你要负责 delete

```cpp
int* p = new int(42);      // 在堆上要了一块"单间"
delete p;                  // 用完还回去

int* arr = new int[100];   // 要了一个"大通铺"
delete[] arr;              // 还回去，注意是 delete[]
```

**为什么不能只 new 不 delete？** 就像你在酒店开房不问前台退房——酒店的内存（房间）被你占着，别人住不了。程序跑久了，内存就被吃光了，这叫**内存泄漏**。

好在 C++11 之后有了**智能指针**，可以帮你自动还回去。详见第五关。

## 第三关：面向对象——把代码组织成"东西"

> 这是 C++ 最核心的设计思想。学会它，你写的代码就能像搭积木一样组合、扩展。

### 3.1 成员方法——让结构体有自己的"行为"

之前的结构体只能存数据（x、y 坐标）。但如果点自己会"缩放"呢？

```cpp
struct Point {
    int x, y;

    void scale(int factor) {   // 这是 Point 的"行为"
        x *= factor;            // 缩放的 x
        y *= factor;            // 缩放的 y
    }
};

Point p{10, 20};
p.scale(2);      // p 自己把自己放大了两倍
```

这样数据和操作数据的代码就放在一起了——这就是**封装**。

### 3.2 const 成员方法——承诺不改数据

```cpp
struct Point {
    int x, y;

    int getX() const { return x; }    // const = "我保证不修改对象"
    void setX(int v) { x = v; }
};

const Point cp{1, 2};
cp.getX();         // ✅ const 对象只能调用 const 方法
cp.setX(3);        // ❌ 编译报错！const 对象不能被修改
```

**`const` 方法的哲学：** 一个方法如果不会改数据，就加上 `const`。这相当于给你的方法贴了个"只读"标签——读你代码的人看到就放心了，编译器也会帮你检查确保你真的没改。

### 3.3 构造与析构——对象的出生和死亡

每个对象都有"出生"（构造函数）和"死亡"（析构函数）：

```cpp
class Fibonacci {
    size_t cache[16];
    int cached;

public:
    Fibonacci() : cache{0, 1}, cached(2) {
        // 构造函数：对象一出生就自动调用
        // 这里初始化了斐波那契缓存的前两个值
    }

    ~Fibonacci() {
        // 析构函数：对象销毁时自动调用
        // 这里不需要做什么，因为 cache 是数组，自动释放
    }
};
```

**出生和死亡的顺序——一个经典规则：**

```
叔叔阿姨先到 → 爸妈后到（构造顺序：基类 → 派生类）
爸妈先走 → 叔叔阿姨后走（析构顺序：派生类 → 基类）
```

就像排队进场和退场——先进去的最后出来（栈一样）。

### 3.4 复制 vs 移动——复印文件 vs 搬桌子

**复制（拷贝构造函数）：** 做一个完全一样的副本。两份都能用。

```cpp
class DynStr {
    char* data;    // 指向堆上的字符串

public:
    // 拷贝构造——深度复制
    DynStr(const DynStr& other) {
        data = new char[strlen(other.data) + 1];
        strcpy(data, other.data);
        // 在另一个地方造了一个一模一样的内容
    }
};
```

**移动（移动构造函数, C++11）：** 把资源从 A 手里"偷"过来给 B。A 手里空了。

```cpp
    // 移动构造——"偷"资源
    DynStr(DynStr&& other) noexcept
        : data(other.data)          // 把指针拿过来
    {
        other.data = nullptr;       // 把原对象的指针置空，防止它 delete
    }
```

**不用纠结，一个场景你就懂了：**

> 你在图书馆借了一本书（资源）。现在你要搬家了：
> - **复制** = 你自己去复印了一本，原件还在你手上，但复印机很慢（花时间、占内存）。
> - **移动** = 直接把书递给新地址的人，你手上空了。**速度极快，零开销。**

### 3.5 继承——子承父业

```cpp
struct Animal {
    virtual void speak() const {
        std::cout << "..." << std::endl;     // 动物的默认叫声
    }
};

struct Dog : Animal {
    void speak() const override {            // override ≈ 确保我真的在重写
        std::cout << "Woof!" << std::endl;
    }
};

Animal* pet = new Dog();
pet->speak();   // "Woof!" — 调的是 Dog 的方法，不是 Animal 的
```

**`virtual` 关键字是关键：** 加上了 `virtual`，方法的调用是"运行时看实际类型"——指针声明的是 `Animal*`，但实际指向的是 `Dog`，所以调 `Dog` 的版本。不加 `virtual`，那就看指针的声明类型，永远是 `Animal` 的版本。

**`override`（C++11）的作用：** 告诉编译器"我就是要重写基类的方法"，如果基类根本没有对应的虚函数，编译器直接报错。**好习惯：每次重写都加上 `override`。**

### 3.6 虚析构——基类指针也能正确析构

```cpp
struct Base {
    virtual ~Base() {}    // 有了 virtual，delete 基类指针时会调用子类析构
};

struct Derived : Base {
    ~Derived() { delete something; }  // 释放子类自己的资源
};

Base* p = new Derived();
delete p;
// ✅ 先调 ~Derived()，再调 ~Base()。子类的资源安全释放。
```

**不加 `virtual` 的后果：** `delete p` 只调了 `~Base()`，`~Derived()` 根本没执行——如果 `Derived` 里有自己 `new` 的资源，**泄漏了**。

> 💡 **何时需要虚析构？** 当这个类被设计为基类（即有人会继承它）时，析构函数就应该是 `virtual` 的。C++ 的这个特性就是"多态地删除对象"。

## 第四关：模板——写一次，用遍所有类型

> 模板是 C++ 最强大的"自动工厂"——你告诉它"我想要个装 int 的盒子"和"我想要个装 string 的盒子"，它自动给你造出来。

### 4.1 函数模板——同一个函数，支持各种类型

```cpp
template <typename T>
T add(T a, T b) {
    return a + b;
}

add(1, 2);           // T = int
add(1.0, 2.0);       // T = double
add(std::string("a"), std::string("b"));  // T = std::string
```

**模板不是运行时的事：** 它是在编译期被"实例化"的。编译器看到 `add(1, 2)`，就生成一个 `int` 版本的 `add`；看到 `add(1.0, 2.0)`，再生成一个 `double` 版本。你写一份代码，编译器帮你生成多份。

### 4.2 类模板——通用的盒子

```cpp
template <class T>
struct Box {
    T value;
    Box(T v) : value(v) {}
};

Box<int> b(42);            // 装 int 的盒子
Box<std::string> s("hi");  // 装 string 的盒子
```

`std::vector<int>` 和 `std::vector<double>` 就是类模板活生生的例子。

### 4.3 Concepts（C++20）——给模板定规矩

**模板最大的痛点**在于报错信息——如果你不小心传了一个不支持 `+` 的类型，编译器会吐出十几页的模板实例化回溯，最后一行才说"哦，不能加"。

**Concepts 就是解决方案：** 给模板参数提前划定"准入条件"。

```cpp
#include <concepts>

template <typename T>
concept Numeric = std::is_arithmetic_v<T>;
// Numeric 要求 T 是数值类型（int、double、float...）

// 限定了 T 必须是数值
auto square(Numeric auto x) {
    return x * x;
}

square(5);          // ✅ int 是数值
square(3.14);       // ✅ double 也是数值
square("hello");    // ❌ 清晰的报错："hello" 不满足 Numeric 约束
```

> 💡 **Concepts 让你从"编译器骂人十页纸"变成"编译器一句话告诉你错在哪"。**

## 第五关：标准库（STL）——C++ 的万能工具箱

> 现实中的 C++ 开发，80% 的工作是在用好标准库。这一关的内容是你实际写代码时天天用的。

### 5.1 std::array——不会退化的数组

传统的 C 数组有个大毛病：传参给函数时就退化成了指针，长度信息丢了。`std::array` 是它的"升级版"：

```cpp
#include <array>

std::array<int, 5> arr = {1, 2, 3, 4, 5};

arr.size();          // 5 — 长度信息一直跟着走
sizeof(arr);         // 20 = 5 * 4 — 在栈上，无额外开销
arr.data();          // 需要和 C 代码打交道时，获取原始指针
```

**用它的理由：** 长度信息永不丢失，支持迭代器，能和 STL 算法直接配合。和 C 数组的性能一模一样。

### 5.2 std::vector——自动扩容的动态数组

**这是 C++ 中使用频率最高的容器，没有之一。**

```cpp
#include <vector>

std::vector<int> vec = {1, 2, 3, 4, 5};

vec.push_back(6);             // 末尾加一个
vec.pop_back();               // 末尾删一个
vec.size();                   // 当前有几个元素
vec.capacity();               // 当前分配了多少容量
vec.reserve(100);             // 提前分配 100 个的空间（避免多次扩容）
```

**理解 size 和 capacity 的区别：** 就像你租了一套房子（capacity），但只住了两个房间（size）。如果来了第三个室友（push_back），你还可以让他住空着的房间。只有当所有房间都住满时，你才需要换一套更大的房子（重新分配内存——非常慢）。所以用 `reserve()` 提前规划能**大幅提升性能**。

**`std::vector<bool>` 的特殊性：** 它不是一个普通的 `vector`。C++ 为了节省内存，把 `bool` 压缩成位来存（一个字节存 8 个 bool）。这听起来很好，但它导致 `operator[]` 返回的不是真正的引用，而是一个"代理对象"——行为和普通 `vector` 不太一样。平时用可以，但别指望 `&v[0]` 能得到 `bool*`。

### 5.3 std::string——真正好用的字符串

C 语言的字符串是 `char*`，操作起来像在刀尖上跳舞——拼接要小心缓冲区溢出，比较要用 `strcmp`，长度要用 `strlen`。

C++ 的 `std::string` 把这些都封装好了：

```cpp
auto s1 = "Hello"s;          // C++14 的 s 后缀，直接得到 string
auto s2 = "world";           // 没加 s → 这是 const char*

std::string result = s1 + ", " + s2 + "!";
// 直接 + 拼接，不用操心缓冲区大小

result.size();               // 长度，O(1)
```

还有一个 C++17 引入的好东西——`string_view`：

```cpp
#include <string_view>

void print(std::string_view sv) {
    // 可以接收各种字符串类型，不拷贝！
    std::cout << sv;
}
```

**`string_view` 就像一个"窗户"：** 透过它你能看到字符串的内容，但你不能拥有它。它不复制数据，只是一个"只读引用"。

### 5.4 关联容器——通过键来找值

**`std::map`** 就是一个"键-值"字典，底层是红黑树（有序）：

```cpp
#include <map>

std::map<std::string, int> ages;
ages["Alice"] = 30;      // "Alice" → 30
ages["Bob"] = 25;        // "Bob" → 25

// 查找
if (ages.find("Alice") != ages.end()) {
    std::cout << ages["Alice"];  // 30
}
```

**⚠️ 注意：** `ages["Alice"]` 如果 `"Alice"` 不存在，会**自动创建一个**（值初始化为 0）。所以查找时最好用 `find()` 而不是 `operator[]`。

**`std::unordered_map`**（C++11）是哈希表版本，查找 O(1) 平均，但不保证顺序。

| | `map` | `unordered_map` |
|:---|:---|:---|
| 底层 | 红黑树 | 哈希表 |
| 查找速度 | O(log n) | O(1) 平均 |
| 有序？ | ✅ 按键排序 | ❌ 无序 |
| 何时用 | 需要有序遍历时 | 大部分场景 |

### 5.5 智能指针——让内存管理自动化

**这是 C++11 带给你最好的礼物。** 在这之前，C++ 程序员最大的噩梦就是忘了写 `delete`。智能指针让这一切变成自动的。

**`unique_ptr`——独占所有权：**

就像一个一次性的钥匙。只能有一个人持有，不能复制，只能转移。

```cpp
auto ptr = std::make_unique<int>(42);
// ptr 是唯一的持有者

auto ptr2 = std::move(ptr);   // 所有权转移给 ptr2
// ptr 现在空了

// 当 ptr2 超出作用域时，int 自动被 delete —— 不需要你写 delete！
```

**`shared_ptr`——共享所有权（引用计数）：**

就像一个合租房的钥匙——每个人都可以配一把，每多一把，计数 +1。最后一个人搬走时，房子自动被清理。

```cpp
auto shared = std::make_shared<int>(10);

auto a = shared;        // 引用计数：2
auto b = shared;        // 引用计数：3

// 当 shared、a、b 全都超出作用域时，int 自动被 delete
```

**`weak_ptr`——旁观者：**

它像一个窗户，可以看到房子里有没有人，但不影响谁住进来或搬走。

```cpp
std::weak_ptr<int> weak = shared;
// 引用计数不变！

if (auto sp = weak.lock()) {   // 通过 lock() 窥探
    // 对象还活着，可以安全使用
} else {
    // 对象已经被释放了
}
```

**老生常谈的经验：** 能用 `unique_ptr` 就别用 `shared_ptr`。`unique_ptr` 零开销，`shared_ptr` 有引用计数的性能成本。只有确实需要共享所有权时才用后者。

### 5.6 常用算法——lambda 的好搭档

**`std::transform`——对每个元素执行操作：**

```cpp
std::vector<int> src = {1, 2, 3, 4, 5};
std::vector<std::string> dst(src.size());

std::transform(src.begin(), src.end(), dst.begin(),
    [](int x) { return std::to_string(x * 2); });
// dst = {"2", "4", "6", "8", "10"}
// 每个 int 乘以 2 并转成字符串
```

**`std::accumulate`——把所有元素"累"起来：**

```cpp
int sum = std::accumulate(begin(arr), end(arr), 0);
// 把 arr 里的所有元素加到一起

int product = std::accumulate(begin(arr), end(arr), 1,
    std::multiplies<int>());
// 把 arr 里的所有元素乘到一起
```

**关于 lambda（就是 `[](){}` 这个东西）：** 它是 C++11 引入的"匿名函数"。你不需要给函数起名字，直接在现场写一段逻辑。上面的 `[](int x) { return ... }` 就是一个 lambda。

## 第六关：C++20 新特性——未来的主流

> 本关全部是 C++20 引入的内容。企业中正在快速普及，你现在学了，工作中就能用上。

### 6.1 Concepts——模板有了"安检门"

模板一直有个大问题：你传错类型时，编译器给你的报错信息就像车祸现场——乱成一团。Concepts 就是在模板入口处加了一道安检门：

```cpp
#include <concepts>

template <typename T>
concept Numeric = std::is_arithmetic_v<T>;

auto square(Numeric auto x) { return x * x; }

square(5);        // ✅ 正常通过安检
square("hello");  // ❌ "hello" 不是数值类型，安检门拦住它并给出清晰的错误信息
```

**Concepts 在现实中的意义：** 如果你写了一个库函数，要求参数必须能比较大小，以前只能用注释告诉调用者："请传支持 `<` 的类型"。现在你可以直接写一个 `Comparable` 概念，编译器会帮你检查——调用者传错了，报错信息第一句就是"不满足 Comparable 约束"。

### 6.2 Ranges——更优雅的链式操作

以前你要对一个数组做"过滤 → 变换 → 收集"这三步，通常要写三四个循环或者套好几层函数。Ranges 让你像流水线一样写：

```cpp
#include <ranges>

auto result = nums
    | std::views::filter([](int n) { return n % 2 == 0; })   // 筛选偶数
    | std::views::transform([](int n) { return n * n; });    // 变成平方

// 什么概念？就像工厂的传送带——
// 原材料（nums）→ 筛选（只要偶数）→ 加工（平方）→ 出成品
```

**Ranges 的意义不在于省代码，而在于代码即文档。** 你把处理步骤按顺序写出来，读代码的人一眼就能看出数据处理的全流程。

### 6.3 std::format——终于有好的字符串格式化了

C 程序员用 `printf`，C++ 老程序员用 `cout <<`，但现在你有了更好的选择：

```cpp
#include <format>

std::cout << std::format("{}, {}!", "Hello", "C++20");
// "Hello, C++20!"

std::cout << std::format("{:.2f}", 3.14159);
// "3.14" — 保留两位小数

std::cout << std::format("{:x}", 255);
// "ff" — 转十六进制
```

**它比 `printf` 好在哪？** 类型安全。`printf("%s", 42)` 在 C 里能编译但运行时崩溃，`std::format` 在编译期就报错。**比 `cout <<` 好在哪？** 更简洁、可读性更好、性能也更高。

### 6.4 三向比较符 `<=>`——一行代替六行

以前如果你想让自定义结构体能比较大小，得写 6 个运算符函数（`<` `>` `<=` `>=` `==` `!=`）。现在：

```cpp
struct Point {
    int x, y;
    auto operator<=>(const Point&) const = default;
};

Point a{1, 2}, b{1, 3};
a < b;    // ✅ 自动比较 x，x 相等时比较 y
a == b;   // ✅ 自动生成
```

**`= default` 的意思是：** "编译器，你帮我把所有比较运算符都生成出来吧"——它先比较 x，x 相同时再比较 y，跟字典排序一样。

### 6.5 协程——函数可以"暂停"了

协程是 C++20 最重要的底层基础设施之一。它允许一个函数在中间暂停，把控制权交出去，等条件满足后再回来继续执行。

```cpp
// 斐波那契生成器（示例需要 C++23 的 std::generator）
std::generator<int> fibonacci() {
    int a = 0, b = 1;
    while (true) {
        co_yield a;           // 暂停，返回 a
        auto next = a + b;
        a = b;
        b = next;
    }
}

for (int f : fibonacci()) {
    if (f > 100) break;
    std::cout << f << " ";    // 0 1 1 2 3 5 8 13 21 ...
}
```

**通俗理解协程：** 普通函数是一次性做完所有事然后返回；协程可以做到一半停下来，说"我先喘口气，回头接着干"。这在处理大量并发请求、流式数据时非常有价值。
